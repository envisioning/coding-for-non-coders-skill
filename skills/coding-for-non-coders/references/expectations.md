# Honest expectations keep the fun in

Use this file to be honest about what one person with AI can build, without taking the fun out of it.

## The first 80 percent is fast

AI gets you roughly 80 percent of the way to almost any app, astonishingly fast. The last 20 percent is where things stay hard: security, logins, storage, scale, and the odd cases nobody thought of. These skills can be learned. They are well documented, and AI can help with each of them. The person only has to ask.

At the first level, the goal is fast prototyping. It can become much more.

## A project moves from prototype to pilot to product

The guide draws one line with three stages and marks the part a person can expect to reach on their own with AI. Treat the prototype as the goal of a first session.

- Prototype: a working version with the key features. The main features work. It is not ready for real use yet. It is good enough to show others, and it helps gather feedback.
- Pilot: tested with real users. It is deployed and reachable. Real people use it. It has basic reliability and security. The scope or the number of users is limited.
- Product: a production-ready application. Security and performance are hardened. It handles scale and odd cases. It has monitoring and maintenance. It may need a team and specialized skills.

At the end of a session, tell the person which stage their project is at and what the next stage would need.

## Code is language, and checking is the skill

Models are good at language, and code is language. What makes them strong at coding is that code can be checked: it runs or it does not. That feedback is what lets models correct themselves.

The same idea is the person's most important skill. Anyone can get code that runs. People who build things worth keeping have a way to check that it is right. "It seems to work" and "I've checked that it works" are the line between a throwaway demo and something to rely on.

## Skills still matter

- AI builds in chunks: a feature, a fix, a flow. The person is still responsible for the result being correct.
- The more you build, the more you value understanding the code. Knowing how user flows, logins and databases work makes better apps.
- AI fills in blanks but cannot make judgment calls. Models often do not know which questions to ask. A basic understanding of each area pays off.
- Software breaks in unexpected places: logins, database queries, calls to other services, odd cases. Understanding these layers makes debugging faster.

## Learning costs little

You can learn and prototype on free tiers of the AI tools and free hosting. The guide's point: cost depends on how much you use the tools, independent of how good you are. Paid plans remove friction such as usage limits.
